# Subtitle formats — SRT / VTT / TXT

How each format is parsed + when to use which.

---

## SRT (SubRip)

Most common subtitle format. File extension `.srt`.

### Structure

```
1
00:00:00,000 --> 00:00:05,000
First caption text here

2
00:00:05,000 --> 00:00:10,500
Second caption,
which can span multiple lines

3
00:00:11,000 --> 00:00:15,000
Third caption
```

Each block:

- Optional numeric index (we ignore it)
- Timecode line: `HH:MM:SS,mmm --> HH:MM:SS,mmm` (comma as decimal separator)
- Caption text (one or more lines)
- Blank line separates blocks

### Where SRT comes from

- **Whisper** (OpenAI) — `--output_format srt`
- **YouTube** — download auto-captions in SRT
- **Premiere Pro / DaVinci Resolve** — export captions as SRT
- **Subtitle Edit, Aegisub, Subler** — dedicated subtitle editors
- **Auto-translation services** — DeepL / Subly export SRT

### Parsing edge cases

- BOM (byte-order mark) at file start: handled
- Windows line endings (CRLF): handled
- Extra blank lines: handled
- Missing index numbers: ignored (we don't use them)
- Inline HTML tags (`<i>...</i>`, `<b>...</b>`): NOT stripped — passed through to ffmpeg drawtext, which doesn't render HTML, so it'll appear literally. Strip your SRT first if you have inline tags.

## WebVTT (.vtt)

Web video standard. File extension `.vtt`.

### Structure

```
WEBVTT

00:00:00.000 --> 00:00:05.000
First caption text

00:00:05.000 --> 00:00:10.500
Second caption
```

Differences from SRT:

- Requires `WEBVTT` header line at top
- Timecode uses `.` (dot) as decimal separator
- No mandatory index numbers
- Supports cue identifiers (optional name before timecode)
- Supports inline tags (`<c>`, `<i>`, `<b>`, `<v>`, `<ruby>`, `<rt>`) — we strip these
- Supports `NOTE` / `STYLE` / `REGION` blocks — we skip these

### Where VTT comes from

- **HTML5 video player exports**
- **YouTube** — alternate to SRT
- **Subly, Submagic, Reduct** — many web-based caption tools

### Parsing edge cases

- WEBVTT header: must be present (auto-detected vs SRT)
- NOTE blocks: skipped
- STYLE blocks: skipped (the skill applies its own styling)
- REGION blocks: skipped
- Inline tags: stripped via regex `<[^>]+>`

## TXT (plain text, evenly distributed)

For when you have caption text but no timing.

### Structure

```
First line becomes one caption.
Second line becomes another.
Third line.
```

One line per cue. Blank lines ignored. The skill:

1. Probes video duration via `ffprobe`
2. Divides duration evenly across N lines
3. Optional 200ms gap between lines (configurable in code)

Example: 30-second video, 3 lines → ~10s per cue.

### When to use TXT

- Quick captioning where exact timing doesn't matter (single static info card video)
- Educational content with timed beats (each line is one "beat")
- Workshop / tutorial videos where each step gets its own caption

### When NOT to use TXT

- Audio-synced narration (use SRT generated by Whisper instead)
- Music videos where captions must hit beats (use SRT from a real timing editor)
- Long videos (>2 min) — even distribution starts to feel mismatched

## Inline (single caption for entire video)

```
subtitle-burner burn ./clip.mp4 --inline "Watch closely."
```

One cue from 0:00 to end-of-video. Useful for:

- Brand intro / outro cards
- Single-message social posts (5-15s reels with one line)
- Trailer text overlays

---

## Choosing the right source

| Use case | Format |
|---|---|
| You have audio narration → caption it | Run Whisper to produce SRT, then this skill |
| You have a short reel with bullet points | TXT (plain text) |
| You have a single-message clip | `--inline` |
| You're cross-posting between platforms | Use the SRT you generated for the source platform |
| You're translating subtitles | Translate the SRT externally, then this skill |
| You want sub-second timing precision | SRT (most precise) |
| You're working in a video editor | Export SRT from Premiere/DaVinci/etc., then this skill |

## Validation

`subtitle-burner preview` parses the source and prints the cue list. Use to verify timing/text before burning:

```
subtitle-burner preview --subtitle ./captions.srt
```

Output:

```
# 12 cue(s) parsed from ./captions.srt

  1.    0.00s →    3.50s  ( 3.50s)  Welcome to the show.
  2.    3.50s →    8.20s  ( 4.70s)  Today we discuss slow software.
  3.    8.20s →   12.10s  ( 3.90s)  And why shipping less can be the right move.
  ...
```

If cues are wrong (out of order, weird timing, garbled text), fix the source before burning.

## Common SRT problems + fixes

### Caption starts before previous one ends

```
1
00:00:00,000 --> 00:00:05,000
First

2
00:00:04,500 --> 00:00:09,000
Second
```

Cue 2 starts before cue 1 ends. ffmpeg renders both simultaneously — captions overlap. Fix the SRT: ensure cue N+1 starts ≥ cue N end time.

### Empty caption blocks

```
1
00:00:00,000 --> 00:00:05,000

2
00:00:05,000 --> 00:00:10,000
First real caption
```

Cue 1 has no text. Skill skips it; final output has only cue 2 onwards.

### HTML tags in text

```
1
00:00:00,000 --> 00:00:05,000
<i>Emphasized text</i>
```

Skill passes through to ffmpeg drawtext, which renders the tags LITERALLY (the user sees `<i>Emphasized text</i>` on screen). Strip the tags from your SRT first:

```bash
sed -i '' 's/<[^>]*>//g' captions.srt  # Mac
sed -i 's/<[^>]*>//g' captions.srt    # Linux
```

### Non-Latin characters (Cyrillic / CJK)

May render as boxes if the system's default ffmpeg font lacks coverage. Workaround:

- Specify a font via `FFMPEG_CAPTION_FONT=/path/to/noto-sans.ttf` env var (planned v2.7).
- For now: edit `common/runners/ffmpeg.py:burn_captions` to add `:fontfile=...` to the drawtext filter.

## Generating SRT from audio (Whisper)

The skill doesn't transcribe — but here's how to generate SRT from audio using OpenAI's Whisper (planned `transcribe` skill will wrap this):

```bash
# Extract audio from video
ffmpeg -i clip.mp4 -vn -ac 1 -ar 16000 clip-audio.wav

# Run via OpenAI Whisper API (requires OPENAI_API_KEY)
curl -X POST https://api.openai.com/v1/audio/transcriptions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -F file=@clip-audio.wav \
  -F model=whisper-1 \
  -F response_format=srt \
  -o clip.srt
```

Or use local Whisper:

```bash
pip install openai-whisper
whisper clip.mp4 --model medium --output_format srt
```

Then feed the resulting SRT to `subtitle-burner burn clip.mp4 --subtitle clip.srt`.
