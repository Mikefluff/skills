# Integration with sub-skills

`writer` сам по себе — редактор. Под-скиллы (`viral-text`, `prose-edit`, `essay-write` и любые будущие текстовые) используют его как обязательный финальный шаг pipeline.

---

## Базовый протокол

Любой текстовый под-скилл в своём pipeline обязан:

1. Сгенерировать черновик по своим правилам (виральный hook, художественный рерайт, эссе и т.д.).
2. Перед выдачей пользователю — прогнать черновик через 4-layer cleaning pass из `writer/SKILL.md`:
   - Layer 1 — regex по 25 категориям нейрослопа (см. `references/neuroslop-categories.md`)
   - Layer 2 — структурная синтетика (см. `references/structural-prose.md`)
   - Layer 3 — хирургические правки (для RU — `references/ru-calques.md` + `references/typography.md`)
   - Layer 4 — чтение вслух
3. Выдать пользователю только финальный текст. Промежуточные шаги — внутренние, не показывать.

Это режим `apply` — writer вызывается без отдельного output для пользователя и возвращает только cleaned text без сводки.

---

## Шаблон обёртки под-скилла

В SKILL.md под-скилла нужна секция «Pipeline» в конце с явным шагом:

```markdown
## Pipeline

1. Извлечь {что-то под-специфическое} из ввода.
2. Сгенерировать черновик по {своим правилам}.
3. **OBLIGATORY:** Применить правила writer/SKILL.md как внутренний редактор —
   прогнать 4-layer cleaning pass (regex 25 категорий + структурная синтетика +
   хирургические правки + чтение вслух) перед выдачей текста пользователю.
4. Выдать финальный текст {в формате X}.
```

## Исключения

Если правила writer противоречат специфике под-скилла, под-скилл явно фиксирует исключение в своей секции.

Примеры реальных исключений:

- **viral-text** — разрешает короткие провокационные предложения подряд в hook'е, что писатель посчитал бы стаккато. В SKILL.md viral-text это явно прописано: «Stop hook can be 2-3 односоставных предложений подряд — это допустимо как hook».
- **prose-edit** — разрешает повторы и неполные предложения в художке (они работают как голос и ритм). В SKILL.md prose-edit это явно прописано: «Художественный текст — не подпадает под бизнес-редактирование».
- **essay-write** — разрешает длинные сложноподчинённые предложения в стиле Мэнсон, даже если это конфликтует с принципом «короткие чёткие предложения».

Если исключения нет — действуют правила writer.

## Обязательное исключение для всех под-скиллов: функциональные элементы

Дефолтное лечение слопа в writer — **удаление**. Для текстов, которые должны что-то сделать, а не только хорошо читаться, это опасно: призыв к действию, оффер, дедлайн, цена, ссылка, контакт, шаг восстановления, команда апгрейда — рабочие детали, а не вода.

Под-скилл, который выдаёт такой текст, обязан лечить их уровнями 2-3 (замена / упрощение), но не удалением, и после прогона проверять, что каждый уцелел хотя бы в одном экземпляре.

Уже прописано в: `landing-copy` (оффер, CTA, цена), `cold-email` (ask, easy-yes, ссылка-пруф), `microcopy` (следующий шаг), `viral-text` (CTA, микровывод), `release-notes` (версии, миграции, breaking changes).

Полное правило — [forbidden-substitutions.md](forbidden-substitutions.md).

## Анти-паттерн: «writer не помог»

Если результат под-скилла приходит к пользователю и пользователь жалуется на нейрослоп — значит pipeline был нарушен.

Признаки нарушенного pipeline:
- В тексте >5 хитов по Layer 1 (regex 25 категорий)
- Длинные em-dashes в виральных постах
- «Не X — а Y» в начале фразы
- 3+ односоставных подряд
- «без X, без Y, без Z» цепочки
- `python3 writer/scripts/lint.py финал.md` вернул код 3 (сработал жёсткий запрет)

Если хоть один пункт сработал — под-скилл забыл вызвать writer. Чинить в SKILL.md под-скилла, а не в writer.

Обратный симптом — **под-скилл вызвал writer слишком усердно**: текст чистый, но у поста пропал призыв к действию, у лендинга оффер, у релиз-нотов команда апгрейда. Это нарушение правила о функциональных элементах выше, чинится там же.

## Где живёт writer

При установке через корневой `install.sh` skill попадает в `~/.claude/skills/writer/`. Под-скиллы ссылаются на него по имени `writer` (Claude Code matcher) — не по пути.
